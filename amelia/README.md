# АМЕЛИЯ

**А**втономное **М**одульное **Е**диное **Л**огико-**И**нтеллектуальное **Я**дро

Локальный ИИ-ассистент, который помнит всё, что тебе важно.

## Как название ложится на архитектуру

| Буква | Смысл | Где в коде |
|---|---|---|
| **А**втономное | всё крутится локально, без внешних API | `core/llm/ollama.py` |
| **М**одульное | навыки — независимые плагины, ядро их не знает в лицо | `modules/` |
| **Е**диное | один вход для всех источников | `core/kernel.py` + `clients/` |
| **Л**огико- | детерминированные правила идут раньше модели | `core/logic/` |
| **И**нтеллектуальное | LLM подключается там, где правила не справились | `core/llm/` |
| **Я**дро | Amelia — движок, а не интерфейс | `core/kernel.py` |

Модульность здесь буквальная: ядро умеет дописывать себе навыки само — см. «Самораcширение».

│   │   ├── llm/            #   -ИНТЕЛЛЕКТУАЛЬНОЕ: провайдеры моделей

│   │   ├── actions/        #   журнал самостоятельных действий и откат
│   │   └── forge/          #   управление навыками: создать/включить/убрать

## Запуск

```bash
python -m amelia cli          # работает сразу, без зависимостей
python -m amelia telegram     # нужен aiogram + BOT_TOKEN
python -m amelia service      # безголовый режим для systemd
```

Без запущенного Ollama ядро живёт: правила работают, `chat` честно скажет, что модель недоступна.

## Круглосуточно на б/у микро-ПК

Целевое железо — списанный корпоративный микро-ПК: Dell OptiPlex Micro,
Lenovo ThinkCentre Tiny, HP EliteDesk Mini. Память в них уже стоит, x86 с AVX2
обгоняет любой ARM-одноплатник на llama.cpp, и живёт это надёжнее SD-карты.
8 ГБ хватает, если брать модель по размеру задачи: `qwen2.5:3b` закрывает
классификацию интентов, JSON для агента и короткие ответы. 7B нужна только
кузнице — под неё имеет смысл отдельная модель.

```bash
sudo bash deploy/install.sh          # пользователь, venv, Ollama, модели, служба
sudo -e /opt/amelia/.env             # токен бота и владелец
sudo systemctl restart amelia
curl -s localhost:8787/health | python3 -m json.tool
```

### Что именно делает круглосуточную работу возможной

Долгий аптайм ломает не то, что видно на десктопе. Здесь закрыто следующее:

| Что убивает сервис | Решение |
|---|---|
| Ollama перезапустилась — ассистент считает её мёртвой навсегда | Доступность с TTL (`llm_probe_ttl`), а не залипающий флаг |
| Переход на зимнее время — все «завтра в 9» уезжают на час | `zoneinfo` вместо целого смещения (`AMELIA_TZ=Europe/Warsaw`) |
| Внезапное отключение питания рвёт базу | SQLite в WAL + `synchronous=NORMAL`, чекпойнт при остановке |
| Журналы и WAL растут, диск кончается | Модуль `upkeep`: ночная подрезка, чекпойнт, еженедельный VACUUM |
| База одна и без копий | Ежедневный онлайн-бэкап через `sqlite3.backup()`, хранится 14 штук |
| Копии лежат на том же диске — умрёт SSD, умрёт всё | `AMELIA_BACKUP_COMMAND` выгружает наружу: rclone, scp, rsync |
| Процесс завис, но не умер | Сторожевой таймер systemd: нет пинга 120 с — перезапуск |
| Рестарт плодит дубли служебных задач | `ensure_recurring()` — одна задача на вид |
| Telegram отвалился и уронил всё | `ServiceClient` перезапускает клиент с нарастающей паузой |
| Утечка памяти съедает машину | `MemoryMax=1G` в юните — Амелию перезапустят, Ollama не тронут |
| SIGTERM обрывает запись | Обработчик сигналов, `TimeoutStopSec=30`, аккуратное закрытие базы |

Состояние ассистента отдаётся по `http://127.0.0.1:8787/health` в JSON:
аптайм, доступность модели, число модулей и инструментов, объём памяти,
очередь задач. Годится и для `curl`, и для внешнего мониторинга.

Одно нельзя сделать скриптом: в BIOS включить «After Power Loss → Power On»,
иначе после отключения света коробка не поднимется сама.

## Три способности, которых у ассистентов обычно нет

### 1. Помнит разговор

`core/session.py`. Раньше каждый запрос был сам по себе — follow-up был невозможен.
Теперь история реплик лежит в SQLite, переживает рестарт и сжимается в выжимку,
когда окно переполняется.

```
› меня зовут Дмитрий, я из Варшавы
› а какая там сейчас погода?     ← «там» = Варшава, Амелия понимает
› забудь разговор                ← контекст сброшен, долговременная память цела
```

Окно — `AMELIA_SESSION_WINDOW` реплик. После `AMELIA_SESSION_COMPACT_AFTER`
хвост уезжает в `session_summaries` одной сжатой строкой. Сессии изолированы
по паре пользователь+клиент: телеграм-разговор не течёт в консольный.

### 2. Строит цепочки действий

`core/agent.py`. Роутер выбирает один модуль — этого мало для «найди в памяти,
посчитай, запиши». Агент даёт модели инструменты и позволяет вызывать их
последовательно, скармливая результат обратно.

```
› какой у меня пароль от вайфая?
  [search_memory] -> найдено
  Пароль от вайфая: morphine2024        (2 шага)
```

Модуль объявляет инструменты методом `tools()` — и всё, агент их видит.
Рамки жёсткие: потолок шагов (`AMELIA_AGENT_MAX_STEPS`), таймаут 30 с на
инструмент, вызов только объявленных имён, любое исключение возвращается
модели текстом вместо падения. Не сработало — откат на прямой ответ модели.

Сейчас в коробке: `save_note`, `search_memory`, `schedule_reminder`, `list_reminders`.

### 3. Существует во времени

`core/scheduler.py`. Ассистент, который умеет только отвечать, — это справочник.
Планировщик даёт возможность действовать самому.

```
› напомни через 20 минут проверить сборку
› напоминай каждый день в 8 зарядка
› напоминания          → очередь с номерами
› отмени напоминание 3
```

Разбор времени — `modules/remind/timeparse.py`, чистые регулярки, без
зависимостей: «через N минут», «завтра в 9», «в 18:30», «каждые 2 часа»,
«в понедельник в 10». Задачи лежат в SQLite и переживают рестарт;
повторяющиеся при пропуске окна перескакивают вперёд, а не срабатывают
пачкой. Сработавшая задача уходит в шину — Telegram-клиент шлёт сообщение,
CLI печатает в консоль.

### Память: приватная, быстрая, без дублей

Три свойства, без которых память перестаёт быть полезной, когда вырастет:

**Приватность по владельцу.** Записи видны только их автору; общие нужно
пометить явно (`scope="shared"`). Раньше `recall()` принимал `user_id`, но его
не передавал ни один вызывающий — пароль одного пользователя находился другим,
и через подмешивание контекста в `chat` это происходило вообще молча.

**Гибридный поиск.** Косинус на питоне линеен: 1000 записей — 182 мс,
3000 — 552 мс, и `chat` дёргает поиск на каждом сообщении. Теперь FTS5
отбирает 60 кандидатов, косинус ранжирует только их: на 1500 записях
поиск занимает единицы миллисекунд и не растёт с базой.

**Дедупликация и свежесть.** Повторное «запомни то же самое» обновляет запись,
а не плодит копии — точное совпадение ловится по тексту, близкое по косинусу
(порог 0.94). Свежесть — мягкий множитель к релевантности: вчерашняя заметка
обходит двухлетнюю, но не вытесняет точное совпадение.

### Поток вместо тишины

На целевом железе 3b выдаёт около десяти токенов в секунду — ответ на сто
токенов это десять секунд молчания. `Request.on_token` — необязательный
приёмник: CLI печатает по мере генерации, Telegram дописывает одно сообщение
раз в секунду. Модули без потока (память, напоминания) отвечают как раньше.

Агент устроен под это: JSON решает, *что вызвать*, а ответ пишется прозой
отдельным потоковым вызовом. Модель больше не собирает экранированную строку
внутри JSON, пока пользователь ждёт.

### Шлюзы у пишущих инструментов

У кузницы пять барьеров между моделью и действием — у агента не было ни одного,
хотя `save_note` и `schedule_reminder` он вызывал сам. Теперь:

- инструмент объявляет `mutates=True`, если меняет данные;
- `AMELIA_AGENT_ALLOW_MUTATIONS=false` убирает пишущие из набора целиком —
  агент остаётся полезным, но только на чтение;
- каждый самостоятельный вызов попадает в `tool_journal` вместе с тем,
  чем его откатить.

```
› действия                      → что Амелия сделала сама
› отмени последнее действие     → откат: заметка удалена, задача снята
```

### Что видит сгенерированный навык

Валидатор ловит `import os`, но не ловит «прочитал всю базу и записал в
заметку»: для этого хватало обычного `self.kernel`. А в `config` лежит токен
бота. Теперь навык получает не ядро, а фасад (`core/forge/sandbox.py`):

| Доступно | Недоступно |
|---|---|
| `memory` — только свои записи, помеченные навыком | `bus`, `scheduler`, `forge`, `modules`, `sessions` |
| `llm` — complete и embed | токен бота, пути к базе, настройки клиентов |
| `config` — модель, зона, размер окна | всё остальное из настроек |

Встроенные модули по-прежнему получают полное ядро — урезается только то,
что написала модель.

### Фиксация языка (актуально для Qwen)

Qwen обучен в основном на китайском и регулярно вставляет иероглифы посреди
русской фразы — особенно маленькие версии и особенно в квантованном виде.
`core/lang.py` — единственная точка, где язык прибивается; раньше её не было
вовсе: три промпта независимо просили «на языке собеседника», два молчали,
а параметры сэмплирования не задавались, то есть работал дефолт Ollama
с `temperature 0.8`.

Три рубежа, в порядке срабатывания:

1. **Сэмплирование.** `temperature 0.3`, `min_p 0.05`, `repeat_penalty 1.1`.
   Главное лекарство: чем выше температура, тем охотнее модель уходит в язык,
   которого больше всего в её обучении. `min_p` предпочтительнее `temperature 0`,
   которая вызывает зацикливание.
2. **Явная директива.** «ОТВЕЧАЙ ТОЛЬКО НА РУССКОМ… ни одного иероглифа»
   уходит в системный промпт всех пяти точек генерации: чат, агент (управление
   и ответ), классификатор интентов, сжатие сессии.
3. **Проверка результата.** Нашлись иероглифы — одна перегенерация с более
   жёсткой формулировкой, и лишь если не помогло — вырезание. Порядок именно
   такой, потому что вырезание ломает смысл: `因为` это «потому что», и без
   него фраза разваливается.

В потоке перегенерации нет — отправленное уже на экране, поэтому куски
чистятся на лету. Эмодзи не трогаются, `<think>…</think>` от Qwen3 срезается.
Статистика видна в «статус»:

```
Язык: auto, иероглифы ловились 3 раза (переписано 2, вырезано 1)
```

Настройки: `AMELIA_RESPONSE_LANGUAGE` (`auto` | `ru` | `en`), `AMELIA_TEMPERATURE`,
`AMELIA_MIN_P`, `AMELIA_STRIP_FOREIGN`.

### Плюс наблюдаемость

`core/trace.py` подписывается на шину и пишет строку JSON на каждый запрос
в `data/trace.jsonl`: модуль, интент, миллисекунды, размер ответа. Без этого
отладка агентных цепочек — гадание. Сводка видна в «статус».

## Самораcширение

Амелия умеет писать себе новые навыки по запросу:

```
› научись считать чаевые от суммы счёта
  Навык «tips» готов и ждёт одобрения.
  файл: amelia/skills/tips.py

› включи навык tips
  Навык «tips» включён.

› чаевые с 2500 на 15
  Чаевые 15%: 375.00 (итого 2875.00)
```

Между «модель написала код» и «код выполняется» стоят пять шлюзов:

1. **Контракт в промпте** — белый список импортов, запрет побочных эффектов при импорте.
2. **AST-валидатор** (`core/forge/validator.py`) — режет `os`, `subprocess`, `socket`, `eval`, `exec`, `open`, дандер-побеги (`__subclasses__`, `__globals__`) и любой исполняемый код на верхнем уровне файла. Не прошло — код на диск не попадает, модели уходит список ошибок на переписывание (до 3 попыток).
3. **Пробный импорт в отдельном процессе** под таймаутом 20 с. Зациклился или упал — статус `broken`, ядро этого даже не заметило.
4. **Ручное одобрение.** Новый навык живёт со статусом `pending` и не грузится реестром, пока не скажешь «включи навык X». Снять этот шлюз можно через `AMELIA_FORGE_AUTO_APPROVE=true` — не надо.
5. **Откат.** «выключи навык X» — код остаётся, «удали навык X» — уезжает в `skills/_trash/`. Всё пишется в `data/forge.jsonl`.

Команды: `навыки`, `научись …`, `покажи навык X`, `включи навык X`, `выключи навык X`, `удали навык X`.

### Чего это НЕ даёт

Валидатор — фильтр, а не песочница: он ловит явное, но статический анализ в принципе обходится. Навык, прошедший все проверки, выполняется с правами процесса Амелии. Поэтому: читай `покажи навык X` перед включением, держи `AMELIA_FORGE_AUTO_APPROVE=false`, а если гоняешь без присмотра — запускай от отдельного пользователя или в контейнере.

## Аудит

`tests/test_regressions.py` — тесты на баги, найденные разбором кода. Каждый
падал до правки. Что чинилось и почему это важно именно для круглосуточной работы:

| Баг | Чем грозил |
|---|---|
| `Config.load` падал на мусоре в `.env` | Под systemd — бесконечная рестарт-петля из-за одной опечатки |
| Исключение в `setup()` модуля роняло запуск ядра | Один кривой сгенерированный навык превращал ассистента в кирпич |
| `OverflowError` на «через 999999999999 дней» | Падение модуля на безобидном вводе |
| «каждые 0 минут» молча становилось разовой задачей | Тихо не то поведение — хуже явной ошибки |
| Планировщик догонял пропуски циклом | Год простоя с минутным периодом — 525 тысяч итераций |
| Трассировка ключевалась по `id(request)` | `id` переиспользуется сборщиком мусора; параллельные запросы путали замеры |
| `user_id` у `recall()` был необязательным | Ровно так и случилась утечка памяти между пользователями |
| Дедуп сливал по вектору без защиты по длине | Сломанная модель эмбеддингов схлопнула бы всю память в одну запись |

Отдельно: заглушка эмбеддингов в тестах использовала встроенный `hash()`,
который рандомизируется на каждый процесс — тест врал примерно раз в шестьдесят
прогонов. Заменена на `crc32`. Флейковый тест хуже отсутствующего.

## Как добавить модуль

1. Создать пакет `amelia/modules/<имя>/`
2. Внутри — класс, наследник `Module`, с `name`, `intents` и `handle()`
3. Всё. Реестр найдёт его сам при старте — ядро править не нужно.
